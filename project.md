# Анализ проекта FPVKADET (FPV-ONLINE)

## 1. Описание проекта
FPVKADET — это браузерный 3D-симулятор FPV-дрона. Он также может быть собран как десктопное приложение благодаря Electron.

### Стек технологий:
- **Движок**: Three.js (3D-графика, камеры, свет).
- **Логика/UI**: React (интерфейс, главное меню, настройки, геймпад-визуализатор).
- **Сборка**: Vite.
- **Обертка под десктоп**: Electron.
- **Особенности**:
  - Реализована кастомная физика управления квадрокоптером (ACRO, ANGLE, SPORT режимы).
  - Поддержка геймпадов и клавиатуры.
  - Наличие нескольких классов дронов: Freestyle 5", Tiny Whoop, Heavy Sync.
  - Динамическая погода (солнце, дождь, снег), ветер и турбулентность.
  - Гонки с круговыми таймерами, кольцами (чекпоинтами) и таблицей результатов.
  - Механика сбрасывания бомбы (с прицеливанием и визуально-физическими эффектами взрыва).
  - Качественный HUD (FPV-камера с помехами, глитчами, эффектами повреждений, OSD-телеметрией).

## 2. Что нужно улучшить (Предложения по рефакторингу)

1. **Модульность движка (`engine.js`)**:
   Сейчас `engine.js` содержит более 600 строк кода и отвечает одновременно за: рендер, спаун бомбы, таймер заезда, обработку клавиатуры, настройки THREE.js сцены. 
   **Решение**: Разбить на логические модули: `InputManager.js` (управление клавиатурой), `RaceManager.js` (обработка чекпоинтов, таймера), `BombManager.js` (управление бомбой и взрывами) и `Renderer.js`.
2. **Физика (`physics.js`)**:
   В данный момент обсчет физики дрона и коллизий (особенно со стенами и бомбой) полностью написан с нуля на векторах. Для более реалистичных отскоков, столкновений со сложной геометрией трассы и взаимодействия объектов друг с другом лучше внедрить библиотеку физики: **Rapier** (через `@react-three/rapier`) или **Cannon-es**. Это даст идеальные столкновения без написания кучи математики с нуля.
3. **Оптимизация рендеринга и HUD (`hud.js`)**:
   Вызовы Canvas 2D API перерисовывают интерфейс на каждый кадр 3D-цикла `animate`. Лучше оптимизировать отрисовку статических элементов HUD (например, компаса и таблицы), выделив их на отдельный слой, чтобы перерисовывать только меняющиеся цифры телеметрии.

## 3. Что можно добавить (Новый функционал)

1. **Глобальная таблица рекордов (Leaderboards)**:
   Сейчас лучшее время круга (`raceTimer.bestLap`) сохраняется лишь временно в памяти (или `localStorage`). Нужно отправлять рекорды трассы на удаленный сервер.
2. **Мультиплеер**:
   Возможность добавить «комнаты», где другие дроны будут летать на одной карте (можно реализовать через WebRTC для P2P обмена координатами с минимальным пингом).
3. **Редактор PID-ов в профиле пользователя**:
   Чтобы пользователи могли сохранять конфигурации (рейты, пиды) в облако и обмениваться ими.
4. **Конструктор трасс (Map Editor)**:
   Позволить игрокам расставлять кольца на карте и формировать собственные заезды, сохраняя их параметры в базу данных.

## 4. Как лучше всего реализовать базу данных (БД)

Учитывая, что фронтенд базируется на React + Vite, интеграция БД должна быть максимально простой, требовать меньше серверного кода и хорошо работать с авторизацией игроков.

### №1. Идеальный вариант: Supabase (PostgreSQL как Backend-as-a-Service)
*Почему это лучший выбор для нас:*
- Отличная и легкая интеграция в **React**.
- **PostgreSQL** под капотом (идеально для сохранения сложной информации, такой как история заездов и настроек).
- Имеет встроенную систему **Auth** (Авторизация через Google, GitHub, Email/Password), что избавит от написания собственного бэкенда для входа игроков.
- Бесплатный тариф покрывает все нужды проекта на старте.

**Что мы сохраним в таблицах Supabase:**
1. `users` — id игрока, nickname, avatar_url.
2. `laps` — track_id, user_id, drone_class, lap_time_ms, date.
3. `user_settings` — сохраненные PID-ы, привязки кнопок контроллера, настройки графики.

### №2. Классический вариант: Node.js (Express) + MongoDB
*Почему это сложнее:*
- Придется отдельно разворачивать сервер на VPS/Render/Heroku.
- Настраивать JWT-токены и безопасность с нуля.
- Потребуется писать роуты API (`/api/leaderboard`, `/api/login`).

**Заключение по БД:**  
Для быстрого и качественного внедрения Leaderboards (Таблицы рекордов), сохранения PID-настроек и авторизации — однозначно стоит использовать **Supabase**. Мы сможем создать бесплатный проект, добавить ключ `SUPABASE_KEY` в `.env` файл в корне проекта и напрямую сохранять/читать рекорды прямо из компонентов React.
